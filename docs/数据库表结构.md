### 1. 核心思路说明

在看代码前，先简单说下设计的几个关键点：

1. **用户体系 (`profiles`)**：Supabase 自带 `auth.users` 表处理登录，我们需要一张 `public.profiles` 表来存你的业务字段（如身份角色、邀请码状态等），并通过 Trigger 自动同步。
2. **标签系统 (`tags` + `work_tags`)**：为了灵活，不要把标签做成 `works` 表里的列。做成独立表，通过多对多关系连接，这样方便你后续增加“ABO”、“哨向”等新标签而不改表结构。
3. **电台 (`radio_messages`)**：区分“便利贴”和“信封”其实是前端的展示逻辑（根据字数渲染不同组件），数据库只存纯文本即可，不需要分表。
4. **邀请码 (`invite_codes`)**：这需要一张独立的表来确权，注册时需要核对。

### 2. SQL 建表语句 (直接运行)

#### 第一步：建立基础枚举和辅助函数

```sql
-- 1. 定义用户角色枚举
create type user_role as enum ('user', 'admin');

-- 2. 启用必要的扩展（用于生成 UUID 等，Supabase 默认通常开启，防呆加一下）
create extension if not exists "uuid-ossp";

```

#### 第二步：用户与邀请码系统

```sql
-- 3. 邀请码表 (用于注册验证)
create table public.invite_codes (
  id uuid default gen_random_uuid() primary key,
  code text not null unique,       -- 邀请码
  email text not null unique,      -- 绑定邮箱
  is_used boolean default false,   -- 是否已使用
  created_at timestamptz default now()
);

-- 4. 用户信息表 (Profiles)
-- 这一张表是对 auth.users 的扩展
create table public.profiles (
  id uuid references auth.users on delete cascade not null primary key,
  username text,
  role user_role default 'user',   -- 默认为认证用户
  avatar_url text,
  created_at timestamptz default now()
);

-- 5. 设置触发器：当 Supabase Auth 创建用户时，自动创建 profile
-- 注意：这里我留了个坑，因为你有邀请码机制，通常建议在后端 API (Next.js API Route) 做校验后再写入。
-- 但为了方便，先写个基础同步，保证用户注册后有 profile。
create or replace function public.handle_new_user()
returns trigger as $$
begin
  insert into public.profiles (id, username, role)
  values (new.id, new.raw_user_meta_data->>'username', 'user');
  return new;
end;
$$ language plpgsql security definer;

create trigger on_auth_user_created
  after insert on auth.users
  for each row execute procedure public.handle_new_user();

```

#### 第三步：图书馆板块 (Works & Tags)

```sql
-- 6. 作品主表
create table public.works (
  id bigint generated by default as identity primary key,
  title text not null,
  author_name text not null,
  original_url text not null, -- 原文链接
  platform text not null,     -- 发布平台 (Lofter, AO3, etc.)
  summary text,               -- 简介
  submitter_id uuid references public.profiles(id), -- 谁提交的
  created_at timestamptz default now(),
  
  -- 约束：同一个 URL 不能重复添加
  constraint unique_work_url unique (original_url)
);

-- 7. 标签定义表
create table public.tags (
  id bigint generated by default as identity primary key,
  category text not null, -- 分类：'类型', '情感', '剧情', '人设' 等
  name text not null,     -- 标签名：'同人文', '甜文', '破镜重圆' 等
  unique (category, name) -- 防止重复标签
);

-- 8. 作品-标签 关联表 (多对多)
create table public.work_tags (
  work_id bigint references public.works(id) on delete cascade,
  tag_id bigint references public.tags(id) on delete cascade,
  primary key (work_id, tag_id)
);

```

#### 第四步：收藏夹板块

```sql
-- 9. 收藏夹文件夹
create table public.favorite_folders (
  id bigint generated by default as identity primary key,
  user_id uuid references public.profiles(id) on delete cascade not null,
  name text not null, -- 文件夹名字，如“必看神文”
  created_at timestamptz default now()
);

-- 10. 收藏夹-作品 关联表
create table public.folder_entries (
  folder_id bigint references public.favorite_folders(id) on delete cascade,
  work_id bigint references public.works(id) on delete cascade,
  created_at timestamptz default now(),
  primary key (folder_id, work_id)
);

```

#### 第五步：电台板块 (Radio)

```sql
-- 11. 树洞留言表
create table public.radio_messages (
  id bigint generated by default as identity primary key,
  user_id uuid references public.profiles(id) not null,
  nickname text not null, -- 自定义留言人名称 (如 "某只章鱼")
  content text not null,  -- 留言内容 (前端判断字数来决定显示便利贴还是信封)
  linked_work_id bigint references public.works(id), -- 可选：引用的作品ID
  created_at timestamptz default now()
);

-- 12. 留言表情表态表 (Reactions)
create table public.radio_reactions (
  id bigint generated by default as identity primary key,
  message_id bigint references public.radio_messages(id) on delete cascade,
  user_id uuid references public.profiles(id) not null,
  emoji text not null, -- 存 emoji 字符，如 '❤️', '😭'
  created_at timestamptz default now(),
  
  -- 约束：同一个人对同一条留言，同一个表情只能贴一次
  unique (message_id, user_id, emoji)
);

```

### 4. 重要的安全策略 (RLS)

Supabase 默认开启 RLS (Row Level Security)。如果不配置策略，前端查不到数据。你需要运行以下策略来开放权限：

```sql
-- 启用 RLS
alter table profiles enable row level security;
alter table works enable row level security;
alter table radio_messages enable row level security;
alter table favorite_folders enable row level security;

-- === 策略示例 ===

-- 1. Works (作品): 所有人可读，登录用户可写
create policy "Works are public" on works for select using (true);
create policy "Users can insert works" on works for insert with check (auth.role() = 'authenticated');

-- 2. Profiles (用户): 所有人可读（为了显示作者名/头像），用户只能改自己的
create policy "Profiles are public" on profiles for select using (true);
create policy "Users can update own profile" on profiles for update using (auth.uid() = id);

-- 3. Radio (电台): 所有人可读，登录用户可发
create policy "Messages are public" on radio_messages for select using (true);
create policy "Users can insert messages" on radio_messages for insert with check (auth.role() = 'authenticated');

-- 4. Favorites (收藏): **只有用户自己可见** (隐私保护)
create policy "Users can see own favorites" on favorite_folders for select using (auth.uid() = user_id);
create policy "Users can manage own favorites" on favorite_folders for all using (auth.uid() = user_id);
create policy "Users can see own folder entries" on folder_entries for select using (
  exists (select 1 from favorite_folders where id = folder_id and user_id = auth.uid())
);

```

### 5. 💡 给学弟/学妹的小建议

1. **关于邀请码逻辑**：Supabase 的注册 (`supabase.auth.signUp`) 是直接调用的。要实现“校验邀请码和邮箱匹配”，你可能需要在 Next.js 写一个 API Route (`/api/register`)。
* 流程是：前端提交 -> Next.js 后端用 `Service Role Key` (超级管理员权限) 去查 `invite_codes` 表 -> 如果匹配 -> 再调用 `supabase.auth.signUp` 注册 -> 注册成功后把邀请码标记为 `is_used = true`。


2. **标签系统**：前端录入作品时，建议做一个多选框（Checkbox Group），把我们刚才 Insert 进去的 Tag 读出来渲染。
